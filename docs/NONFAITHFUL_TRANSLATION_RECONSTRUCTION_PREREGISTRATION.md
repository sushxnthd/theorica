# Nonfaithful translation reconstruction: preregistration

Classification: **DISCRIMINATION / THEOREM-CORRECTION / CAPABILITY-BUILDING**.

## Active kernel

- **Precise question:** is injectivity of the carrier-to-translation map actually necessary for exact translation-base reconstruction?
- **Best-known frontier in this repository:** the published theorem and learner require faithfulness and classify nonfaithful racks/quandles as outside scope.
- **Exact objective:** prove or refute necessity, exhaust every operation with permutation rows through carrier size four, minimize any counterexample, and implement the resulting exact conditional capability.
- **Strongest alternative:** faithfulness is required because repeated signatures prevent row identification or because the current subgroup may be incomplete.
- **Cheapest decisive falsification:** hold the full generated group fixed and test whether a group base identifies each translation even when multiple carrier elements select the same group element.
- **Publishable success condition:** a sharp necessary-and-sufficient identifiability theorem, exact finite enumeration, independent checker, primary-priority audit, and prospective validation on previously excluded public nonfaithful algebras.
- **Project-relevance threshold:** the theorem must change THEORICA's accepted representation class and yield executable exact reconstruction, not merely simplify a proof.
- **Kill condition:** any promised operation with noninjective translation map fails reconstruction from a genuine base, or the correction has no executable scope consequence.

## Frozen theorem candidate

Let `G <= Sym(S)` be generated by `r` fully queried translation rows, and suppose every left translation `L_x` belongs to `G`. For a common coordinate set `B`, every table in this promise class is exactly identifiable from the generator rows plus `F(x,b)` for unqueried rows and `b in B` **if and only if** `B` is a base of `G`. The map `x -> L_x` need not be injective.

The exact cached-query upper bound is

`r n + (n-r)|B|`,

not merely the earlier loose `n(r+|B|)` bound.

Necessity is restricted to common-coordinate identification over the full promise class: if `B` is not a base, choose distinct `g,h in G` agreeing on `B`; two operations differing only by assigning `g` versus `h` to one unqueried carrier element have identical queried transcripts but different tables.

## Frozen exhaustive test

- Enumerate every `n`-row table whose rows are permutations for `n=1,2,3,4`: exactly `sum((n!)^n)=331,997` operations.
- For each table, generate `G` from its realized rows, find a minimum subset of realized rows generating `G`, find a minimum group base, reconstruct every row from its base signature, and compare the complete table.
- Record faithful and nonfaithful counts separately.
- Search increasing `n` for the smallest nonfaithful operation rejected by the current learner but reconstructed by the corrected conditional theorem.
- PASS requires zero reconstruction failures and a minimal counterexample at `n=2`; otherwise FAIL.

## Holdout boundary

This run uses exhaustive synthetic finite domains and existing opened code only. It must not open the public nonfaithful-algebra challenge before the theorem, implementation, tests, and external protocol are frozen.
